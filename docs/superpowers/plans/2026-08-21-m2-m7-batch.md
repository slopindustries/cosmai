# M2–M7 일괄 실행 계획 (배치 모드)

> 오너 지시(2026-08-21): M2~M7을 최대 워크트리 병렬로 연속 실행. 적대적 리뷰는 **M7에서 전체 1회**(+수리 웨이브). 기계적 게이트(mypy·ruff·pytest·가드)는 커밋마다 유지. 마일스톤당 브랜치 → dev `--no-ff` 병합(정지 없음). **유일한 오너 정지점 = M7의 main 병합 + v0.1.0.**
> 이 계획은 배치(디스패치 브리프) 단위다 — 복사·개작 구간의 명세는 P0 참조 트리와 계약 문서 자체이고, 신규 개발(M5·신규 어댑터)만 두껍게 적는다.

**Spec:** `docs/superpowers/specs/2026-08-21-p1-reconstruction-design.md` + DP-029~034 + `contracts/experimental/`(CONTRACT-JOB-0.1, CONTRACT-ADDON-1.3, POC-CONTRACT-0.1) + `docs/architecture-synthesis/P1-RECONSTRUCTION-PLAN.md` M2~M7 행.

## 레인 구조와 의존성

```
Lane A(임계): M2 domain ──→ M3 애드온 3층 ──→ M4 애드온 fan-out(애드온당 워크트리)
Lane B: M5 대시보드 — 즉시 착수(M1 API+P0 참조), M2/M6 API 착지 후 통합

```

## 공통 제약 (M1 global-constraints 승계 + 추가)

- 브랜치: `p1/m2-domain`, `p1/m3-addon-layer`, `p1/m4-<addon-id>`(워크트리별), `p1/m5-dashboard`, `p1/m6-ops`, `p1/m7-closure`. 각 레인 게이트 통과 시 dev에 `--no-ff` 병합. push 금지.
- **레인 간 인터페이스 계약**: P0의 API 라우트·응답 형태가 기본 계약. 이 계획 §신규 API가 정의하는 것 외에 레인이 임의로 표면을 바꾸면 결함. 변경이 필요하면 dev에 먼저 병합된 쪽이 이긴다.
- **레인별 테스트 DB**: Lane A=`cosmai_test`, B=`cosmai_test_2`, C=`cosmai_test_3`, M4 워크트리=`cosmai_test_4`(공유, 애드온 테스트는 순차) — M2 배치 2a가 프로비저닝 + conftest `COSMA_TEST_DB` env 허용을 만든다. 병렬 pytest가 같은 DB를 치면 스키마 리셋 경합(OQ-006 기록)이 재현된다.
- 샌드박스: env 파일·:5433·docker exec·uv 캐시는 unsandboxed. 서브에이전트 파견 시 매번 명시.
- 시크릿·계층·복사·개작 규칙은 M1과 동일. 편차는 침묵하지 않고 각 레인 기록(`docs/p1/M<N>-RECORD.md`)에 등재 — M7 리뷰가 대조한다.

## 신규 API (레인 간 계약 — 형태 고정)

- `POST /sources/{source_id}/credentials` `{purpose: str, value: str}` → 204. **쓰기 전용**(DP-034: 응답 에코·로그 금지, `~/.config/cosmai/env`에 `COSMA_SRC_<ID>_<PURPOSE>=` 기록, 화면엔 ref와 설정 여부만). 구현: M5 레인(백엔드+UI 일체).
- `GET /export/raw?source_id&from&to&key_prefix&format=jsonl|csv` → 스트리밍. `GET /export/results?...&format=csv`. 구현: M6.
- `GET|PUT /sources/{source_id}/schedule` `{interval_seconds: int, enabled: bool}`; 스케줄러가 due 시 collect 잡 생성. 구현: M6.
- domain 라우트(M2): P0 `addon_host/__main__.py`의 `extend_with_domain` 표면 재현 + raw 아이템 페이지네이션 조회 `GET /sources/{id}/raw/items?offset&limit`(DP-033 D2 — payload는 plain text로 반환, 렌더 지시 없음).

## M2 — domain (Lane A, `p1/m2-domain`)

원본: `experiments/integrated-p0/domain/` (store.py, migrate.py, outbound.py, transport.py, migrations 0002~0005) + P0 domain 테스트. 결정: DP-029(수정 3건), DP-030 D2(레코드 단위 내성), DP-019/024(봉투), DP-018(credential parts).

- **배치 2a — 테스트 DB 병렬화 + 마이그레이션**: `cosmai_test_2/3/4` 프로비저닝(provision.md 절차 재사용, 부 B+C 반복); conftest `TEST_DATABASE = os.environ.get("COSMA_TEST_DB", "cosmai_test")`; 마이그레이션 0002(domain) 작성 — P0 0002~0005를 하나로 통합하되 **DP-029 반영**: `raw_item.seq bigint generated always as identity`(D2), `schedule` 테이블(spec §4.2), 전부 `cosmai.` 한정·timestamptz.
- **배치 2b — store 코어**: DomainStore 복사·개작. **필수 편차 3건**: ① 스냅샷 멤버 선택 = 동일 `item_key` 중 `seq` 최대(D2 — P0의 `emitted_at`/uuid 낙하 제거, 동률 회귀 테스트: 같은 트랜잭션 2행 → 최신 seq 선택 12회 재봉인 동일), ② 매니페스트 정렬 = UTF-8 **bytewise**(D3 — `ORDER BY convert_to(item_key,'UTF8')` 또는 앱측 바이트 정렬; 회귀: 로케일 흉내 정렬과 다른 케이스), ③ `canonical_body`의 고립 서로게이트 → **레코드 단위 `normalize_error` 결측 처리, 실행 계속**(DP-030 D2 — P1-INHERITED-DEFECTS §1 수리; 회귀: 불량 1행+정상 2행 → 결과 3행, 에러 1 집계). 실체화 봉인·이중 digest 검증·완료 트랜잭션 enlist(DP-010)는 P0 원문 유지.
- **배치 2c — outbound·transport·credential parts**: P0 복사·개작(프로파일 구조·protected header·리다이렉트 재검증 로직 유지 — SR-001은 강제 *수위*의 이관이지 구조 제거가 아님). M1의 over-redaction 편차(credential_ref 마스킹)를 여기서 마주하면: ref 이름은 안전 표시 대상 — redaction 규칙에 `credential_ref` 키 예외를 추가하고 M2-RECORD에 등재.
- **배치 2d — domain API + 시나리오**: `extend_with_domain` 재현 + raw 페이지네이션 라우트(§신규 API); P0 domain 테스트 + 스냅샷 변조/재생/버전 공존 시나리오 복사·개작 + 위 회귀 3건. `docs/p1/M2-RECORD.md`(편차 대장 포함) 작성 후 dev 병합.

## M5 — 대시보드 (Lane B, `p1/m5-dashboard`, 즉시 착수)

`apps/dashboard/`: Vite+React 19+TS+**MUI+React Router+TanStack Query**(DP-033 D4). P0 dashboard는 화면 구성·API 소비 형태의 참조. 화면 6종(DP-033 D1)과 착수 순서:

- **배치 5a — 스캐폴드 + 잡 모니터링 + 헬스**: M1 API로 즉시 개발 가능. 라우팅 골격, API 클라이언트(TanStack Query), 잡 목록/상세/attempt/재시도, 헬스·메트릭. P0의 SSR 텍스트 렌더러는 재현하지 않음(B 범위에서 유일하게 생략 — M5-RECORD에 기록; pytest 대신 vitest+testing-library로 대체).
- **배치 5b — 크리덴셜 쓰기 경로**: `POST /sources/{id}/credentials` 백엔드(platform api 확장; DP-034 D1/D2: 값은 요청 1회 경유, env 파일 append, 로그·에코 금지, 응답 204; `CONFIGURATION_INVALID` 구분) + 수집기 화면의 입력 폼(쓰기 전용, ref·설정 여부 표시). 백엔드 테스트: 파일 반영·재표시 불가·로그 부재.
- **배치 5c — 수집기 도메인 화면 + 자료 브라우저** (M2 병합 후): 도메인당 수집기 하나 단위(목표 6), 상태·config 폼(manifest config schema 렌더)·작업 이력·마지막 성공; 자료 브라우저 = raw 아이템 페이지네이션 + **payload plain-text 렌더**(DP-033 D2 — markup 해석 금지, 테스트로 단언: `<script>` 포함 payload가 텍스트로 보임).
- **배치 5d — 정규화 관리 + 다운로드 화면 + 스케줄 UI** (M2·M6 병합 후): 스냅샷 선택→run 생성→버전 공존 열람; 다운로드 폼(범위조건→`/export/*` 링크); 스케줄 편집. 통합 스모크: 실제 API에 붙여 6화면 수동 경로 기록. `docs/p1/M5-RECORD.md`.
